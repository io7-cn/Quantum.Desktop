# 桌面数据验收

[English](../en/desktop-data-validation.md) · [安装与更新](desktop-releases.md) · [问题 #8](https://github.com/io7-cn/Quantum.Desktop/issues/8)

使用一次性 Windows 账户或虚拟机及合成数据，记录候选提交、安装包 SHA-256、Windows 版本、安装路径、执行结果和两次确认弹窗截图。不要使用真实用户数据库。仓库的 `test` 和 `windows` 检查仍是必需门禁；文件系统和 PowerShell 流程自动测试不能替代安装包级验收。

1. 在默认位置安装候选包并启动。确认生成的 MAUI 发布者为 `io7-cn`，数据库、个人插件、日志、设置和安全状态均写入安装目录之外的 `%LOCALAPPDATA%\io7-cn\io.quantum.desktop`。安装插件，写入可辨认的记录并修改语言设置。
2. 从 Windows 设置卸载。确认默认选择保留、显示路径正确，取消后应用仍已安装。再次选择保留，等待卸载成功，重装并验证记录、插件、语言设置和登录状态仍可用。
3. 测试删除选择。确认第二次确认默认拒绝删除；拒绝后安装仍存在。再次操作并确认删除，检查两个固定数据目录已清除，重装为干净状态。在外部 `QUANTUM_MODULES_PATH` 放置标记文件，确认它始终保留。
4. 执行注册的 `QuietUninstallString`，确认没有数据弹窗、数据保留且重装恢复记录。模拟更新器卸载失败，确认数据仍在；继续前恢复候选安装。
5. 在旧 `%LOCALAPPDATA%\Quantum\io.quantum.desktop` 中准备设置、安全状态及含已提交 WAL 记录的 SQLite 数据库，在 `current\Modules` 中准备正常和禁用插件。关闭旧应用，将两处备份到安装目录之外，再安装候选包。旧更新器移除插件时，按发布指南的过渡步骤恢复插件。启动后验证迁移记录和插件行为，确认原文件未改动。修改新目录中的记录后重启，旧数据不得重复导入。
6. 分别制造插件文件冲突、无效数据库、旧目录不可读、新目录已有内容但没有完成标记。启动必须明确报错，不能提交部分数据或空数据库。解决问题后重试。在源路径或目标祖先中添加目录联接，确认会被拒绝。验证迁移失败且数据仍仅在旧目录的安装，不能通过注册的包装入口卸载，须先解决迁移。
7. 将已成功迁移的候选版本更新到第二个测试包，确认数据和插件保留，更新完成钩子在正常启动前就已恢复卸载选择入口，且仍可卸载重装。另测试自定义安装目录，确认发布包在 `Quantum.exe` 旁包含 `Uninstall.ps1`。

验收负责人将证据记入问题和 PR。独立审查、必需 CI 和上述安装包验收通过前，保持问题开放。macOS 继续使用原有系统数据位置；移除 `.app` 会保留这些位置，不执行 Windows 卸载器。

候选版本需要回滚时，保留并备份新数据根目录。旧文件副本用于诊断，但新应用写入后它们会过期；不得静默切回旧副本或覆盖新记录。应通过明确的恢复流程还原已验证备份。
